MULTI-TENANT ISOLATION
Every white-label recruitment campaign must be isolated by organisation.
Requirements:
1.	One organisation must never see another organisation’s candidates, vacancies, reports, branding, communications, or analytics.
2.	Enforce tenant isolation at the server and database-query levels.
3.	Do not rely only on frontend filtering.
4.	Every organisation-owned record must be associated with the correct tenant.
5.	Authorisation tests must specifically test cross-organisation access attempts.
6.	Administrative users must only access tenants within their assigned authority.
7.	Super Admin access to client data must be audited.
8.	Any cross-client reports must use aggregated and anonymised data.

•	Paying for career services does not guarantee verification.
•	Paying for career services does not guarantee shortlisting.
•	Paying for career services does not improve a candidate’s match ranking.
•	Result Seekers does not sell jobs.

WHITE-LABEL DEFINITION OF DONE
White-label recruitment is complete only when:
1.	Result Seekers can create an isolated client recruitment workspace.
2.	The client can have approved branding.
3.	The client can use a dedicated path, subdomain or verified custom domain.
4.	Public vacancy and application pages reflect the approved branding.
5.	Recruitment emails use approved client branding.
6.	Reports support approved branding.
7.	Result Seekers can manage the campaign centrally.
8.	Client users see only their own information.
9.	Candidate consent and privacy responsibilities remain enforceable.
10.	Legal roles such as recruiter, data controller and data processor are not misleadingly concealed.
11.	Tenant isolation has automated tests.
12.	Custom-domain security has been verified.
13.	Closing or removing a client campaign does not delete required recruitment records.
14.	Result Seekers can revert the campaign to a safe default domain.
15.	Branding configuration cannot inject unsafe code.
